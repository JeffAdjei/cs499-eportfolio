Grazioso Salvare Dashboard (CS 340)

Narrative · Original & Enhanced Artifact Reflection

What the artifact is

The artifact is a Python / MongoDB dashboard built for CS 340 Client/Server Development. It pairs an AnimalShelter CRUD module (PyMongo) with a Jupyter ProjectTwoDashboard built on Dash that visualizes and filters the Austin Animal Center data for the Grazioso Salvare rescue-dog training company.

Why I included it

I chose this artifact for the databases category because it is a realistic full-path example: a client (the dashboard) talking to a service (the CRUD module) talking to MongoDB. It lets me show growth in query design, validation, and the trade-off between filtering in Python vs. filtering in the database — which is exactly the kind of decision that matters in production.

Enhancements

Safer CRUDExplicit validation in create/update/delete to prevent unintended bulk operations and invalid documents.
Query EfficiencyAdded projection, sort, and limit support so reads return only what the dashboard needs.
Filter in DBFiltering moved into MongoDB queries instead of pulling the whole collection into memory and filtering in Python.
Error HandlingTyped exceptions (ConnectionFailure, OperationFailure, PyMongoError) and helper methods for clearer failure modes.

Course outcomes demonstrated

  • Outcome 3 — Design & evaluate computing solutionsPushing filtering into MongoDB and adding projection/sort/limit is an explicit evaluation of where computation should live, against real efficiency trade-offs.
  • Outcome 4 — Innovative techniques, skills & toolsUses MongoDB idioms (projection, sort, limit) and PyMongo typed exceptions rather than ad-hoc loops.
  • Outcome 5 — Security mindsetGuarding against unintended bulk operations and validating CRUD inputs mitigates the most common self-inflicted database failures.
  • Outcome 2 — Professional communicationDocstrings, a clear class-level summary of the Milestone Four improvements, and this narrative document the why behind each change.

Reflection on the process

The biggest lesson was that the database is not just a bucket — it is a computation engine, and using it that way changes how you design everything above it. Once I pushed filtering into MongoDB, both the dashboard and the CRUD module got simpler and faster. The other lesson was the value of explicit failure modes: replacing a generic except Exception with typed PyMongo errors made the code honest about what can actually go wrong, which is something I will keep doing on future data systems.
