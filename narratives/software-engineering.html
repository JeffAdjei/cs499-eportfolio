Software Engineering & Design

Weight Tracking Mobile App (CS 360)

Narrative · Original & Enhanced Artifact Reflection

What the artifact is

The artifact is an Android weight tracking application originally developed for CS 360 Mobile Architect & Programming. The original app allowed users to log in, create an account, record daily weights against a target, and grant optional SMS permissions for milestone notifications. It was built with Java activities, XML layouts, and a SQLite database helper.

Why I included it

I selected this artifact because it demonstrates the full stack of classic software engineering concerns — user interaction, persistent storage, input validation, and application structure — on a real mobile platform. It is also the clearest example of production-style code I wrote during the program, which made it the ideal candidate to show growth in software design and engineering for the capstone.

Enhancements

I enhanced the application along four intentional axes without changing its core user value. The goal was to make the code behave more like a professionally maintained codebase:

Input ValidationStronger checks on login, account creation, and weight entry to prevent invalid state and unsafe inputs.
Modular DesignActivities refactored into focused helper methods (e.g., initializeDatabase, initializeViews, setButtonListeners) for readability and reuse.
Database LayerCleaner DatabaseHelper responsibilities; safer query and write paths.
MaintainabilityDocumentation comments and consistent naming so another engineer could pick up the code without friction.

Course outcomes demonstrated

  • Outcome 3 — Design & evaluate computing solutionsRefactoring the activities into focused methods and restructuring the database helper shows the ability to evaluate an existing design and redesign it against software engineering standards.
  • Outcome 4 — Innovative techniques, skills & toolsApplying modular design, defensive input validation, and clean SQLite access demonstrates use of well-established engineering practices in a real mobile platform.
  • Outcome 5 — Security mindsetTighter input validation and safer database access reduce the surface area for invalid or malicious input.
  • Outcome 2 — Professional communicationCode comments, naming, and this narrative itself communicate design decisions to a future reader.

Reflection on the process

The most valuable part of this enhancement was the shift in mindset from "make it work" to "make it maintainable." Extracting helper methods and revisiting validation forced me to read my own code through the eyes of another engineer, which is the perspective I want to keep as I move into professional work. I also learned that small structural improvements — a focused helper, a clearer boundary between UI and data — compound into a significantly more readable codebase. No blockers were unsolvable; the main trade-off was scope discipline: resisting the urge to rewrite features beyond what the capstone goals required.
